# RAG 链路设计原理与改动原因（2026-09-11 版）

> 本文回答"**为什么这样设计**"与"每次改动**为什么发生**、效果如何、边界在哪"。
> 逐模块的机制细节（函数、参数、数据结构）见 `docs/RAG_PIPELINE_DETAILED.md`；
> 评测口径与基线见 `docs/EVALUATION.md` 与 `docs/RAGAS_EVAL_GUIDE.md`；
> 踩坑史与复用清单见 `docs/RAG_OPTIMIZATION_LESSONS.md`。

## 一、链路总览（一次问答经过谁）

```text
问题
 ├─ 查询扩展（Multi-Query + HyDE + 多轮补全，≤4 条，失败降级原问题）
 ├─ 每条查询：kNN(60) + BM25(60) ── 单路 RRF ── 每路取 32 child
 ├─ 跨查询 RRF 合并（source 轮流保底，取 40）        ← S1 书名加权在此
 ├─ S3′ 书内检索（点名书：来源过滤下 kNN+BM25，top3 保底进池）
 ├─ Parent-Child 聚合（small_to_big 取 ≤10 parent）  ← S1 保底 / S2 目录降权 / S6 查询级保底
 ├─ BGE cross-encoder 精排（10 → 6）                ← S1 精排加成 / S2 目录扣分
 └─ S5 相关度门槛（top1 < 0.2 → 0 来源直答）
生成（/api/chat 或 Agent 工具链）
```

评分/改进都围绕这条链的**三段**：召回（能不能找到）→ 选择（把谁放进 6 个
名额）→ 门槛（该不该答）。2026-09-11 的全部改动是对"选择"段和"门槛"段的
工程化，以及对评测的度量体系建设。

## 二、既有设计为什么长这样（历史理由）

| 设计 | 为什么 | 关键数据/出处 |
|---|---|---|
| kNN + BM25 混合 | 语义（同义表述）与词面（专名/术语）互补，单路各有盲区 | 早期评测：专名题 BM25 强、表述题 kNN 强 |
| RRF 融合（不是直接加权求和） | 两路分数量纲不可比，排名融合免调参且鲁棒 | 项目基线（README） |
| Parent-Child（child 320 定位 / parent 600 给上下文） | 小块定位准、大块语义完整；直接切大块会稀释相似度 | `docs/INDEX_REDESIGN_PLAN.md`、切分实验（8% 落句界） |
| 查询扩展（Multi-Query+HyDE） | 用户口语与库内书面语错位；《书名》类问法必须扩展 | 2026-08 之前 l1 类题 recall 归零的修复 |
| cross-encoder 精排 | 双塔相似度对"问句↔段落"判断力有限；精排显著提 prec | 08-26 检索优化（prec 0.476→0.769） |
| source 轮流保底（merge 阶段） | 同书 epub+pdf 双格式会垄断候选池 | 08-26（l2-kb-006 修复之一） |

## 三、2026-09-11 新增层：现象 → 根因 → 方案 → 效果

### S1 书名感知路由（retriever.py / service.retrieve）
- **现象**：5/21 题用户点名了书，正确书被压到第 2-6 位（逐题记录见
  `docs/EVALUATION.md` 的 id 与说明）。
- **根因（信号不对称）**：书不自称（正文说"本书"），书名主要出现在**其他书**
  的引用里 → BM25 命中的是引用块；kNN 分不出同主题书；**RRF 双路加成反而
  偏袒引用块**（两路都靠前），目标书只有语义一路。全链路没有实体匹配通道。
- **方案**：问题里的《书名》→ 归一化匹配来源文件名 → 三层注入：
  ① 融合分 ×2（竞争位次）；② 每本保底 3 个 parent 进池（防被硬截断）；
  ③ 精排分 +0.1 再截断（防"进池但排最后"）。**加法 0.1 而非乘法**：能翻
  0.38↔0.48 的量级，翻不动 0.9 vs 0.1 的差距（保 precision）。
- **安全设计**：篇名（不是文件名）→ 匹配不到自动退化原行为。
- **效果**：source_recall 0.95→1.00、MRR 0.847→0.897、RAGAS prec +0.068。

### S2 目录块治理（同函数族）
- **现象**：某题输出 6 槽里 4 槽是目录页（章节词密度高 → BM25 与 reranker
  都给高分），正文块被挤；全局普查 20 题占 17 槽（14%）。
- **方案**：`is_toc_like`（"目录"开头或"第X章"≥4 次）→ 融合层 ×0.7 +
  精排层 −0.08。**为什么是"轻"降权：**强降权（×0.5/−0.15）实测误杀"清单型
  答案"（清单类书目的答案就在目录页，7/7→2/7）并砍掉合法覆盖（目录条目
  覆盖参考中的一处提法）→ 加了**枚举题豁免**（哪些/哪几/列举）。
- **效果**：目录占槽 17→4；被误伤项全部恢复。

### S3′ 书内检索（store.search_* 加 filter_rel_path + book_scoped_children）
- **现象**：点名书的正文块持续被引用块/同主题书压（S1 的三层注入只能改善
  排序，不能改善"书内哪些块被召回"）。
- **方案**：点名书 → 在其来源过滤下再跑一次 kNN+BM25（书内竞争小），
  top3 保底进池。**边界**：对"书内深处的具体句"无效（60+/107 名外）——
  这类缺口是覆盖问题不是排序问题（见 RAGAS_EVAL_GUIDE 第七节）。
- **效果**：MRR ≈0.90 稳定，命名书输出位次前移。

### S5 相关度门槛（service.ask）
- **现象**：检索永远返回 top-k，库外问题拿随机块喂生成模型。
- **方案**：top1 < `kb_chat_min_score`(0.2) → 不调 LLM，0 来源直答。
  校准：库外 6 题 top1 0.002~0.116，库内 20 题最低 0.537 → 阈值取 0.2
  （宁可漏拦不误杀；"推荐科幻电影"0.578 是已知硬例，不为 1 个样本加规则）。

### S6 查询级公平（ensure_parents，多话题触发）
- **现象**：多跳题 l2-kb-006 需要两篇不同篇章（同属一个文件，source 分流
  管不到文件内部），分数制选择让单一话题垄断池子。
- **方案**：多话题（≥2 个《》）时，每个扩展查询（话题探针）的 top-1
  parent 保底进池。**哲学复用**：与 source 分流、S1 保底同构——把"公平"
  从文件级推进到查询级。
- **效果**：l2-kb-006 池内污染被挤出，输出 6/6 主题相关。

## 六、可对外讲的三条设计原则（面试版）

1. **信号完整性**：每一层只会处理它"看得见"的信号——词频看不见实体、
   语义看不见书目、排序融合看不见来源。缺的信号要用**元数据通道**补
   （S1/S3′ 的本质），而不是在既有层上调参。
2. **保底与公平**：排行榜式选择天然会垄断（同书双格式、单话题、引用块）——
   在"截断点"之前布设**配额/保底**（source 分流、书名保底、查询保底），
   比事后调权重稳。
3. **度量驱动**：先归因（缺口死在那一层）、再做方差受控的对照实验、
   用确定性指标做内环、LLM 裁判只做验收——今天的每个决定（含 4 个否决）
   都出自这条流水线，而不是直觉。
