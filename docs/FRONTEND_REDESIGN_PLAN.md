# 前端改造方案：视觉系统升级与体验优化

> 2026-09-30 讨论稿（**待逐阶段确认后开工；本方案自身不含代码改动**）。
> 背景：前端功能已齐（对话 / 知识库 / 运行记录 / 文档查看器 / 设置七标签 / 记忆面板），
> 但视觉是逐轮功能叠加长出来的——两套调色板并存、部分对比度不达标、无任何响应式、
> 动效覆盖不均、尺度无刻度。本方案拆成可独立验收的阶段：先固化基线，再统一地基，
> 然后清理与"美化"，最后补响应式/动效；交互升级单开计划。
> 开工前先读本文；数字口径：2026-09-30 实测（方法见附 A/附 B）。
>
> 状态：**阶段 0 素材已备**（基线截图首轮已拍、对比度审计已跑通，见 §1.1）；
> 阶段 1–4 待确认；阶段 5 待单独立项。

## 0. 目标与非目标

**目标**

1. **视觉统一**：消灭两套调色板（Element Plus 默认色 vs 项目令牌）与无刻度的圆角/字号取值；
2. **"好看"**（阶段 3 专项）：配色取向、层级与阴影、留白与密度、字号阶梯、空态/错误态视觉语言、
   图标风格、动效气质——各给具体提案。注意：只做令牌归一交付的是"一致"，不是"好看"；
3. **可访问性**：文本对比度达到 WCAG AA（当前实测 34 组中 13 组不达标，集中在浅色次要文本与语义色）；
4. **体验补课**：响应式断点（当前 0 个）、动效覆盖（3 个主页面中 2 个零动效）、局部交互细节（阶段 5）。

**非目标（明确不做，防范围蔓延）**

- 不换 UI 框架、不重写组件库使用方式（继续 Element Plus 2.9.x；根因是缺映射层，不是 EP 本身）；
- 不在本方案内加新功能（记忆面板搜索、命令面板等 → 阶段 5 单开计划）；
- 不整体重写/全量拆分巨型 SFC——拆分是**代价**不是收益阶段；只允许在阶段 2/3 必须改动的
  区域随手抽取子组件，且**只搬不改**；
- 不动后端接口与数据契约；不引入 Tailwind 等新 CSS 框架（令牌 + 原生 CSS 变量已足够）。

## 1. 现状勘查（全部实测，明细见附 B）

### 1.1 基线素材（已完成的侦察）

- 浅/深基线截图已拍首轮（聊天、知识库、运行记录、设置对话框、记忆面板共 10 张）；
  阶段 0 会把截图脚本与固定清单入库后**重拍为正式基线**；
- 对比度审计已跑通（附 A 全表）：34 组中 13 组不足以用作正文；
- 审计脚本已修正一个已知坑（"色值行 `#ffffff ...` 被当注释整行跳过"），
  阶段 0 复制进仓库（`scripts/contrast_audit.py`）。

### 1.2 设计令牌（`src/styles/theme.css`，155 行）

- 已有 31 个变量：背景层次 8 / 边框 2 / 文本 3 / 品牌 5 / 语义 4（仅 danger、success）/
  气泡与标签 7 / 阴影 2；深色一套同步（底色 #0e1014→#1a1d24 蓝灰系）；
- **完全缺失尺度类令牌**：radius / spacing / font-size / motion / z-index / focus-ring。

### 1.3 两套调色板并存（"两种蓝"的根因）

- `main.js` 同时加载 EP 浅色与深色 css-vars；`src/` 里**没有任何 `--el-*` 映射层**
  （只有 theme.css 末尾 3 条 `html.dark .el-*` 组件补丁）；
- EP 默认主色 `#409eff` 与项目 `--primary #1677ff`、渐变紫 `#6f5bff` 同屏出现——
  全站 44 处 `type="primary"` 的按钮走 EP 蓝；
- **EP 调色板被手抄 30+ 处**：`#67c23a / #e6a23c / #f56c6c / #909399` 及派生
  `#b3e19d / #fdf6ec / #e1f3d8 / #fbc4c4` 等（多作 `var()` fallback，个别裸写，如
  ChatView 3412 `border-color: #e6a23c`、4049 `background: #f56c6c`）；
- **fallback 写反**：`var(--text-2, #909399)`——项目令牌的 fallback 用 EP 值
  （DirPicker / RunsView / PdfViewer 多处）；
- **打过内联补丁**：ChatView 3926/3930 `--el-switch-on-color: #1677ff`——映射层缺失的直接证据；
- **第三套色**：RunsView 的 ECharts 硬编码默认调色板
  `#5470c6/#91cc75/#fac858/#ee6666/#3ba272/#999`，且无主题监听（只监听 resize），
  深色下图例/轴文字仍是默认深灰。

### 1.4 对比度实测（34 组 / 13 组 < 4.5:1；深色全过、浅色集中翻车）

- 次要文本 `--text-3` #8b909b：白底 3.20 / 侧栏 3.12 / 卡片 3.02——而它正是 11~13px 的主力字号
  （全站 12px ×35 处、13px ×31 处、11px ×16 处）；
- 语义色当文字：success 2.56、danger 2.90、联网标签 2.25；
- 主色当链接文字：4.10（不足 4.5）；
- EP 调色板当文字全部不达标：#909399 3.08 / #409eff 2.78 / #67c23a 2.24 / #e6a23c 2.19 / #f56c6c 2.90。

### 1.5 尺度无刻度

- border-radius **15 种**取值（10px×23、8px×20、4px×12、999px×9、12px×8、6px×6、14px×6…）；
- font-size **14 种**（11 / 11.5 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 16 / 17 / 18 / 20 / 24）；
- z-index 仅手写 2 处（2、5）；自绘浮层与 EP dialog（默认 2000+）之间没有层级体系。

### 1.6 响应式与动效

- **全 `src/` 0 个 `@media`**；会话栏折叠是手动按钮，不随窗口宽度自适应；
- transition/animation：ChatView ~24 处、App ~12 处，**KnowledgeView / RunsView 0 处**。

### 1.7 巨型单文件（维护性，非本方案主线）

- ChatView.vue **4232 行**（模板 1–914 / 脚本 916–2559 / 样式 2561–4232）；
- App.vue **2818 行**（模板 1–1151 / 脚本 1153–2030 / 样式 2032–2818）；
- 内联 style 共 11 处；ChatView 首行残留垃圾字符 `wo`（已确认不进构建产物，顺手清掉）。

### 1.8 机制缺失

- package.json 只有 dev/build/preview——**无 lint**，裸 hex 没有任何防回退机制；
- 可沿用的先例：`frontend/ui_*_check.mjs`（Playwright 回归脚本）与 pre-commit 钩子
  （提交时跑全量后端测试，357 个约 35s）；
- Playwright 在 `frontend/node_modules` 实际可用，但未在 package.json 声明——阶段 0 顺手声明或文档化。

## 2. 分阶段方案（每阶段独立提交、独立验收；顺序=可感知收益在前，不可见重构在后）

### 阶段 0 — 基线固化（零视觉变化）

1. `frontend/ui_shot_check.mjs` 入库（沿用现有 ui_*_check.mjs 的 launch/截图模式）：
   固定清单——3 页面 × 浅/深 × {空态 / 正常 / 长内容溢出 / 错误态 / 流式中} + 设置对话框 + 记忆面板；
   截图统一写 `scratch/check_outputs/`（沿用现有 ui_*_check 脚本约定，已 gitignore）；
2. `scripts/contrast_audit.py` 复制入库（附 A 的生成器）；
3. 基线档案：正式截图清单 + 附 A 报告（作为"改前"基准）。

**验收**：一条命令出全套截图；对比度数字可复现。

### 阶段 1 — 令牌补全 + EP 映射层（地基，收益最大、风险最低）

1. 补齐尺度类令牌：`--radius-{sm,md,lg,xl}`、`--space-{1..6}`、`--font-{xs,sm,base,md,lg,xl}`、
   `--dur-{fast,base,slow}` + `--ease-{out,inout}`、`--z-{dropdown,sticky,overlay,modal,toast}`、
   `--focus-ring`；
2. 补语义色：warning / info / success-soft 等（浅深两套）；
3. **修正不达标文本色**（实测候选，附 A 有换算）：
   - `--text-3`: #8b909b → **#6b7280**（白 4.83 / 侧栏 4.71 / 卡片 4.56 / 计划底 4.59）；
     选中底 #eef4ff 场景实测 4.38 略欠——实现时二选一：该场景用 #656b76（4.85）或把选中底转浅；
   - 新增 `--primary-text`: **#0958d9**（蓝文字/链接专用，5.56~6.16；按钮底与图形仍用 #1677ff）；
   - 新增 `--success-text` **#0f7a4a**（5.38）与 `--danger-text` **#d4380d**（4.80）；
     现有 success/danger 保留作图形与边框色；
   - `--web-tag-text`: #e8912d → **#8a5210**（5.82）；
4. **EP 映射层**（浅深两份）：`--el-color-primary` 及其 `-light-3/5/7/8/9`、`-dark-2`
   全部指向项目令牌（派生色用 `color-mix(in srgb, var(--primary) N%, white)`，
   深色按深底混合；不依赖 color-mix 时落静态色值表亦可）；success / warning / danger / info 同理；
   EP 自带中性灰体系随映射整体收起；
5. 顺手合并：theme.css 末尾 3 条 `html.dark .el-*` 补丁并入映射段；删除 ChatView 开关内联补丁。

**验收**：浅/深截图对照（EP 组件的蓝/绿/黄/红与自绘区域一致）；裸 hex 计数不增；
附 A 修正组全部 ≥4.5（白字蓝底按钮等非正文场景显式豁免并记录）。

### 阶段 2 — 硬编码清理 + 尺度归并 + 防回退

1. 裸 hex → 令牌：等于令牌值的直接替换；EP 调色板残留（含 fallback 颠倒写法）改语义令牌；
2. ECharts 主题化：抽 `chartPalette`（浅深两套），RunsView 监听主题变化 setOption；
   轴/图例文字、网格线改用令牌；
3. 尺度归并到阶段 1 令牌（**像素级变化 → 逐页签认**；允许新旧并存、随改随清）；
4. 防回退：stylelint 或轻量守门脚本（`scripts/check_frontend_hex.mjs`，挂 pre-commit）——
   裸 hex 计数只降不升，白名单（如内联 SVG 装饰色）显式列出；
5. 顺手清：ChatView 首行 `wo`；可安全消除的内联 style。

**验收**：裸 hex 报表（前后对比）；签认记录；`npm run build` 通过。

### 阶段 3 — 视觉设计 pass（"美化"本身）

> 前三个阶段交付"一致"；本阶段回答"好看"。以下为具体提案，逐项可单独讨论、逐页签认。

1. **配色取向**：保留品牌蓝 #1677ff（与产品名调性一致、已渗透进多处渐变）；确立
   "蓝色=品牌动作"原则（按钮/选中/链接用蓝，其余收敛为中性灰阶）；全站 11 处
   linear-gradient 收敛到品牌位（logo / 欢迎图标 / 发送按钮）+ 必要的进度语义色，其余去渐变；
2. **层级与阴影**：两档阴影扩展为三档（内联卡 / 悬浮项 / 弹层）；深色下以边框+微弱提亮替代大阴影；
3. **留白与密度**：4/8/12/16/24/32 间距刻度落地到消息流、设置表单、卡片内边距；
4. **字号阶梯**：正文 14 / 次要 13 / 元信息 12 / 标题 16–24；消灭 4 个 .5 档（11.5/12.5/13.5/14.5）；
5. **空态/错误态视觉语言**：统一"图标 + 一句主文案 + 一个动作"模板（会话空态 / 知识库空态 /
   记忆空态 / 工具失败卡 / 检索零命中）；
6. **图标风格**：统一 EP 线性图标（尺寸 14/16/20 三档），去掉面性混用；
7. **逐页重做点**（各配对照截图）：
   - 欢迎页：建议卡补齐容器感（边框 + 悬浮态），去掉"几乎裸文"感；
   - 消息 / 来源 / 工具卡：统一卡头结构（图标 + 标题 + 状态徽标）；
   - 记忆面板：长内容两行截断 + 展开、分类标签强化、"命中/时间"合并为一行 meta、
     操作按钮降权（删除收进更多菜单）；
   - 设置：标签图标放大、主题预览卡升级为真实缩略图；
   - 运行记录：图表主题化后的视觉核对 + 统计卡数字字号阶。

**验收**：逐页浅/深对照截图 + 用户签认。

### 阶段 4 — 响应式 + 动效

1. 断点：≥1440（现状）/ 1024–1440（会话栏默认折叠）/ <1024（会话栏改抽屉）/ <768（单列，
   内容宽度自动全宽）；
2. 动效令牌落地：120/200/320ms + 标准 easing；给 KnowledgeView/RunsView 补过渡
   （列表进入、抽屉、图表初始）；主题切换过渡扩展到卡片/边框；
3. `prefers-reduced-motion` 支持。

**验收**：三档宽度 × 浅深截图；动效时长 grep 检查。

### 阶段 5 — 交互升级（单开计划，本文档只登记候选）

- 记忆面板：搜索、按分类筛选/分组、长列表虚拟滚动、归档视图区分（当前 46 条，会继续增长）；
- 会话：搜索/置顶；消息级操作（重试某条 / 引用回复）；可选 ⌘K 命令面板；
- 全局键盘与可达性：焦点环、Tab 序、快捷键一览（审批卡已有一轮键盘支持，扩展到全局）。

**依赖**：阶段 1–4 的令牌与组件沉淀完成后立项。

## 3. 风险与收益

| 阶段 | 收益 | 风险 | 缓解 |
|---|---|---|---|
| 0 | 一切改动可对比、可回归 | 无 | 纯新增脚本/文档 |
| 1 | 双蓝双灰消失、对比度过线、后续美化地基 | 映射层影响全部 EP 组件，个别位置色变 | 浅深截图对照；只动色不动布局 |
| 2 | 硬编码收敛、防回退机制 | diff 大、像素级变化难评审 | 逐页签认；只降不升守门；新码新刻度 |
| 3 | 真正解决"还是原来那样" | 审美主观 | 每项配对照图逐项签认 |
| 4 | 窄窗可用、动效统一 | 断点与 EP 组件交互回归 | ui_shot_check 固定清单回归 |

## 4. 提交与验收约定

- 提交前缀：阶段 1–4 用 `style(frontend):`（纯样式）/ `refactor(frontend):`（结构）；文档用 `docs:`；
- 每阶段统一验收：`npm run build` 通过 + 浅/深截图 + 控制台无报错 + 裸 hex 不增（阶段 2 起）；
- 像素级视觉变化（半径/字号归并、配色修正值）**逐页签认**，不做"顺手清理"；
- pre-commit 会跑全量后端测试（357 个，~35s）；本方案不改后端，预期恒过。
