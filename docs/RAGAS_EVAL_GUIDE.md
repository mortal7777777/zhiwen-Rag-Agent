
# RAGAS 评测详解：口径、设计原因与效果对比（2026-09-11）

> 回答三个问题：① 四指标到底在量什么、我们怎么配置的、**为什么**这么配；
> ② answer_correctness 为什么"看起来很低"；③ 各种波动从哪来、怎么甄别。
> 基线数据见 `docs/EVALUATION.md`；经验教训见 `docs/RAG_OPTIMIZATION_LESSONS.md`。

## 一、为什么是"快慢双轨"而不是只用 RAGAS

RAGAS 是 **LLM 裁判**：全量 31 题约 30 分钟，且存在结构性噪声（见第五节）。
它的定位是**验收**（外环）。日常迭代依赖另一个内环：

| 轨道 | 工具 | 判定方式 | 成本 | 用途 |
|---|---|---|---|---|
| 内环 | `evaluate_retrieval.py --batch` | 规则判定（字符串匹配） | ≈3.6s/题 | 改检索后第一时间看方向 |
| 外环 | `eval_ragas.py` | LLM 裁判 | 20-30 分钟 | 验收、记基线、对外汇报 |

设计原因：如果每次参数调整都跑 RAGAS，迭代成本高一个数量级；而如果只看快
指标，"回答质量"又没人把关。两轨各司其职是 2026-09-11 全部实验能低成本完成的
前提。

## 二、四指标在量什么（判分机制）

RAGAS 四个指标全部由 **judge 模型**（跟随当前激活对话供应商，这里 deepseek）
完成判定，没有人工标注：

| 指标 | 输入 | 判分过程 | 语义 |
|---|---|---|---|
| **Faithfulness** | 答案 + 检索上下文 | ① 把答案拆成陈述句；② 逐句做 NLI（是否由上下文支持） | 答案有没有"无中生有" |
| **AnswerCorrectness** | 答案 + 参考答案 | ① 双方拆事实点，算事实 F1；② 嵌入算语义相似度；③ 按 `weights` 加权 | 答案与参考的事实一致度 |
| **ContextPrecision** | 上下文 + 参考答案 | 逐个上下文判断"对得到参考答案有用吗"，按序计平均精度 | 检索结果有多少是有用的 |
| **ContextRecall** | 参考答案 + 上下文 | 把参考拆句，逐句找"上下文里有依据吗" | 参考内容的覆盖率 |

实现细节（`eval_ragas.py`）：
- 用 **legacy API**（`ragas.metrics`）+ `evaluate()`：0.4.3 的 `evaluate()`
  只接受 legacy 指标体系，collections（下一代 API）会报 TypeError；
- **逐题评测**（每题一次 `evaluate()`，做完立即落盘）——为了断点续跑；
- 题库支持两个跳过旗标：`skip_reference_metrics`（拒答类题）、
  `skip_faithfulness`（S5 门槛后拒答题返回空上下文，faithfulness 恒 0 无意义）。

## 三、我们的配置与"为什么"（逐项）

1. **AnswerCorrectness 权重 = [0.5, 0.5]**（2026-09-11 起；此前 [1.0, 0.0]）。
   - 旧配置（纯事实 F1）的代价：**同义转述一律不算分**——不依赖嵌入、实现
     简单，但对"答对但措辞不同"系统性扣分。
   - 对照实验（同一批答案/上下文，只换权重，六题）：
     | id | [1,0] | [0.5,0.5] | Δ |
     |---|---|---|---|
     | l1-kb-001 | 0.000 | 0.396 | +0.396 |
     | l1-kb-005 | 0.400 | 0.437 | +0.037 |
     | l2-kb-006 | 0.159 | 0.793 | +0.634 |
     | l2-kb-011 | 0.120 | 0.446 | +0.326 |
     | l2-kb-012 | 0.204 | 0.470 | +0.266 |
     | l2-kb-009 | 0.710 | 0.820 | +0.110 |
   - 语义半边用**本地 BGE 适配器**（`ProjectEmbeddingsAdapter`，同时实现了
     legacy 的 embed_*/aembed_* 与 collections 的 text/texts 两套接口名）。
   - 代价：ac 历史值（tag `2026-09-11` 及更早）与新口径**不可直接比较**，
     基线已按新口径重打（见 EVALUATION.md）。
2. **judge = 当前激活供应商 + 三个加固**：`RAGAS_DO_NOT_TRACK=true`（遥测
   会走系统代理卡死）、`httpx trust_env=False`（绕 Clash）、`thinking
   disabled` + 120s 超时 + 重试。这些每一条都对应一次实测卡死。
3. **容差带（regression_gate）**：faith 0.03 / ac 0.08 / prec 0.05 / rec 0.05
   ——按实测的 run-to-run 波动幅度设定；单题跌幅 >0.3 只提示不拦截。
4. **拒答题（l2-kb-015）全部停测**：参考答案描述"库里没有"，与四个指标的
   语义全部错位（prec/rec 恒 0、faithfulness 恒 0），行为验证改由 API 端
   （0 来源 + 模板回复）承担。

## 四、answer_correctness 为什么低（"不应该啊"的完整解释）

先给结论：**这是度量口径问题，不是回答质量问题**。回答质量看 faithfulness
（~0.96）与 rec/prec（~0.79/~0.88，快指标 source_recall 100%）。ac 偏低的
四个机制（按贡献排序）：

1. **旧口径砍掉了语义半边**（已修，见上）。修前 l2-kb-011 这类"答对但换了
   措辞"的题只有 0.12。
2. **体裁错位**：模型回答是"结论 + 依据列举"的长文本，参考是 36~152 字的
   要点短句。事实 F1 双向惩罚——答案里参考没写的真事实算"多余"，参考里答案
   没逐字说的算"遗漏"。**答得越丰富越吃亏**。
3. **检索抽样决定答案侧重点**：同一题两轮检索召回的段落不同 → 答案强调的
   事实不同（l2-kb-011 在 s1 轮 ≈0.99、s2 轮 ≈0.12，两轮答案都正确、都源自
   库内，只是与参考的重合点不同）。
4. **裁判重复性**：同答案同上下文重掷裁判，实测摆动 0.05~0.16；再叠加答案
   跨轮变化，单题 ac 总波动可达 ±0.3~0.4。

**正确用法**：ac 看均值和趋势，不看单题绝对值；要抬它，优先动口径（已做）
与参考答案丰富度，而不是改回答风格。

## 五、波动来源与甄别方法论

| 波动源 | 量级 | 应对 |
|---|---|---|
| 查询扩展（Multi-Query/HyDE 是 LLM 生成） | 单题检索结果跨轮不同；快指标 ±1 题 | 对照实验固定扩展结果（方差受控）；结论看多次 |
| 生成（答案措辞/侧重微变） | ac 单题 ±0.2~0.4 | 同上 |
| 裁判（逐句判定的 LLM roll） | 单题 ±0.05~0.16 | 重掷甄别（下） |

**单题大跌甄别法（3 分钟）**：`python eval_ragas.py --id <ids>`——复用检索
缓存（同答案同上下文），只重掷裁判。结果稳定 → 真信号（查检索/参考）；
结果回升 → 噪声。当日 l1-kb-008 rec 0.5→1.0→0.0→0.5 的"过山车"就是靠它
澄清的。

## 六、效果对比（2026-09-11 全程）

| 阶段 | 快指标（rec@6 / MRR / kw@6） | RAGAS 均值（faith / ac / prec / rec） | 备注 |
|---|---|---|---|
| 修复前全量（21 题） | 0.95 / 0.847 / 0.65 | 0.948 / 0.378 / 0.741 / 0.730 | tag `2026-09-11`（ac 旧口径） |
| S1+S5 后（tag s1） | 1.00 / 0.897 / 0.75 | 0.974 / 0.363 / 0.809 / 0.808 | ac 仍旧口径 |
| S2+S3′ 后（tag s2） | 1.00 / ≈0.90 / 0.70~0.75 | 0.962 / 0.334 / 0.785 / **0.875** | ac 仍旧口径；rec 主收益 |
| S6+新题+ac 新口径（tag s3） | 1.00 / **0.918** / **0.77**（30 题） | **0.980 / 0.593 / 0.793 / 0.858**（30 题口径） | ac=[0.5,0.5]（口径变更，与上行 ac 不可比）；题库 31 题 |

**公开基准（CMRC2018 dev 切片，独立索引，`eval_cmrc.py`）**：
- 检索（120 题 / 848 段语料，本管线 kNN+BM25+RRF+BGE 精排）：
  **recall@1 = 0.992 · recall@6 = 1.000 · MRR = 0.993**；
- 生成（同批 120 题，回答由本管线 top-6 上下文 + 对话模型生成）：
  **EM(严格) = 0.000 · EM(包含) = 0.942 · F1(字符近似) = 0.303**——
  本模型输出为"结论+依据"的解释文体，金答案是短片段，严格 EM 恒 0 属
  体裁差异；**包含式 EM 0.942** 才反映"回答里是否含正确内容"；F1 为
  字符集合近似而非 SQuAD 口径，仅作参考。
- 解读：CMRC 段落检索是"偏易"基准（语料仅 848 段、段落主题区分度高，BM25
  单独召回就有 0.8+），0.99 说明管线在标准中文阅读理解上**没有短板**；但
  不能据此声称在"大语料开放域"同样强——自建 60k 块知识库上的真实表现在
  **快指标 + RAGAS 基线**里。

## 七、已知边界（写在墙上，勿重复实验）

- keyword_recall 上限 ≈0.75-0.80：两个短语在书内 60+/107 名之外，**问题驱动
  检索不可达**（已用书内排名实测）；
- l1-kb-009 类"宽泛主题题"的覆盖不对称：问题太泛 → 书内命中的是序言性内容；
- S4（扩池/扩输出）方差受控实验对上述缺口全部无效，已否决；
- 自建集 n=31、单机 60k 块语料：绝对数值不与他人横向比较，只做自身纵向基线。
